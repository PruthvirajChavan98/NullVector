# NullVector Codebase Audit: Patchwork & Over-Engineering

> **Date**: 2026-03-15
> **Scope**: Full repository analysis — source, tests, docs, config, git history
> **Verdict**: The codebase has strong domain modelling but suffers from half-completed
> migrations, speculative abstractions, and documentation that describes a completely
> different project. Every finding below is backed by file paths and evidence.

---

## SECTION 1: DOCUMENTATION IS FICTION

The three `docs/` files and the current `CLAUDE.md` are **generic project templates** that
describe a completely different application. They were never customized for NullVector.

### 1.1 `docs/architecture.md` — Describes a FastAPI Web App

| Claim in docs | Actual reality |
|---------------|----------------|
| "Hexagonal with `api/`, `services/`, `core/`, `adapters/` layers" | No such directory structure exists. Actual layout: `domain/`, `ingest/`, `llm/`, `tree/`, `retrieval/`, `storage/`, `semantic/` |
| "`api/routers/` — FastAPI APIRouter instances" | `api/__init__.py` is an empty placeholder. No FastAPI anywhere. |
| "`adapters/persistence/` — Uses sqlalchemy[asyncio]" | No SQLAlchemy in dependencies or code. Storage uses custom `DocumentStore` protocol. |
| "`adapters/cache/` — Redis adapter" | No Redis anywhere. |
| "`adapters/messaging/` — SQS, RabbitMQ" | No message queue anywhere. |
| "Dependency injection via FastAPI `Depends()`" | No DI framework. Services take protocols as constructor args. |
| "Configuration via `pydantic-settings.BaseSettings`" | `pydantic-settings` is not in dependencies. Config uses plain Pydantic models. |
| ADR table references ADR-001 through ADR-008 | Actual ADRs are numbered 0000-0008 with completely different content (PDF parsing, tree pipelines, LLM gateways) |

**Impact**: Any AI assistant (or new developer) reading these docs will make wrong
assumptions about every architectural decision.

### 1.2 `docs/coding-standards.md` — Phantom Dependencies

| Claim | Reality |
|-------|---------|
| "pyproject.toml should have `asyncio_mode = 'auto'`" | Not configured. Tests don't use pytest-asyncio. |
| "ruff select should include `C4`, `PT`" | Actual select: `["B", "E", "F", "I", "PTH", "RUF", "SIM", "UP", "W"]` — no C4 or PT |
| "mypy should have `warn_unreachable = true`" | Not configured. |
| "`pytest-mock`'s mocker fixture" for mocking | `pytest-mock` is not in dev dependencies. Tests use manual mock adapters. |
| "markers: integration, e2e" | No markers configured in `pyproject.toml`. |

### 1.3 `docs/development-workflows.md` — References Tools That Don't Exist

| Claim | Reality |
|-------|---------|
| "Pre-commit hook in `.pre-commit-config.yaml`" | File does not exist. No pre-commit hooks. |
| "`commitlint` enforced in CI" | No commitlint. Recent commits are literally just date strings: `14032026`, `13032026`. |
| "Changelogs generated by `git-cliff`" | No git-cliff configuration. |
| "`docker compose up -d` for postgres + redis" | No `docker-compose.yml` exists. |

### 1.4 `CLAUDE.md` — Same Template Problem

Mirrors the same phantom references: `pytest-asyncio`, `pydantic-settings`, `core/exceptions.py`
(doesn't exist), `core/constants.py` (doesn't exist — actual file is `src/nullvector/constants.py`),
`core/logging.py` (doesn't exist — actual file is `src/nullvector/observability/logging.py`).

## SECTION 2: HALF-MIGRATED CODE (PATCHWORK)

### 2.1 Three Artifact Store Patterns Coexist

The diff introduces a new storage abstraction but leaves two old ones alive:

| Pattern | File | Status |
|---------|------|--------|
| `ArtifactStore` (old Phase 01) | `src/nullvector/ingest/artifacts.py` | **DEAD CODE** — no longer imported by modified services |
| `AcquisitionArtifactStore` (old Phase A) | `src/nullvector/ingest/acquisition_artifacts.py` | **DEAD CODE** — replaced by `RunScopedStore` in `acquisition_service.py` |
| `DocumentStore` + `RunScopedStore` (new) | `src/nullvector/storage/protocol.py` | **ACTIVE** — used by modified services |

Both old classes still exist as importable modules. Anyone reading the codebase sees
three different ways to persist artifacts with no indication which is canonical.

### 2.2 `json_safe` Defined in Three Locations

| Location | Role |
|----------|------|
| `src/nullvector/storage/_serialization.py` (line 27) | Canonical definition |
| `src/nullvector/_serialization.py` | Re-export shim |
| `src/nullvector/ingest/artifacts.py` (line 14) | Imports from the shim |

Three levels of indirection for a single utility function. Same applies to
`settings_digest` and `canonical_json_bytes`.

### 2.3 `tree/service.py` Mixes Two Persistence Models

The 978-line `tree/service.py` uses:
- **New pattern**: `store.read_json_artifact(ref)`, `store.put_json(...)` via `RunScopedStore`
- **Old pattern**: `_read_json(Path(...))`, direct `Path` manipulation

Both patterns appear in the same file, sometimes in adjacent methods. The migration
was started but not completed.

### 2.4 Deleted `multimodal_gateway` Still Referenced

The entire `src/nullvector/llm/multimodal_gateway/` sub-package is deleted in the diff,
but cookbook notebooks still import from it:
- `cookbook/nullvector_langgraph_cookbook_v2.ipynb`
- `cookbook/01_nullvector_ingestion.ipynb`
- `cookbook/02_nullvector_langgraph.ipynb`

These will crash at import time.

### 2.5 Deleted `observability` Modules Still Conceptually Present

`observability/bus.py`, `observability/events.py`, `observability/subscriber.py` are
deleted and replaced by `observability/logging.py`. However, the subscriber pattern
(`subscribers/json_logger.py`, `subscribers/rich_progress.py`) still exists and uses
the old event-based model. The migration from event bus to stdlib logging is incomplete —
subscribers accept structured event dicts but the new `log_event()` function writes
directly to Python loggers.

### 2.6 `StrataModel` Base Class Survives Project Rename

The project was renamed from StrataForge to NullVector (commit `f723640`), but:
- `StrataModel` remains the base class for all 100+ domain types (`domain/common.py`)
- Every model in `domain/tree.py`, `domain/ledger.py`, `domain/events.py`, etc. inherits from `StrataModel`
- The name appears hundreds of times across the codebase

## SECTION 3: OVER-ENGINEERING

### 3.1 `DocumentStore` Protocol — 21 Methods, 120-Line Delegation Wrapper

`src/nullvector/storage/protocol.py` defines a `DocumentStore` protocol with **21 abstract
methods**. Then `ScopedDocumentRun` (lines 244-362) is a 120-line dataclass that exists
solely to delegate every call by prepending `run_type`/`run_id`/`document_id`:

```python
# This pattern is repeated 11 times:
def put_json(self, *, artifact_kind, artifact_path, payload):
    return self.store.put_json_artifact(
        run_type=self.run_type, run_id=self.run_id,
        document_id=self.document_id, artifact_kind=artifact_kind,
        artifact_path=artifact_path, payload=payload,
    )
```

The `FilesystemDocumentStore` (314 lines) then implements 21 methods, but **four of them
are identical** — `json_artifact_ref`, `jsonl_artifact_ref`, `text_artifact_ref`, and
`binary_artifact_ref` all do:

```python
def json_artifact_ref(self, *, run_type, run_id, document_id, artifact_path):
    del run_type, run_id, document_id
    return str(self._path(artifact_path))
```

The filesystem backend ignores most protocol parameters because they only matter for
PostgreSQL. This is a protocol designed for the most complex backend, forcing the simple
backend to carry dead parameters.

### 3.2 Legacy Compatibility Baked Into Brand-New Code

`FilesystemDocumentStore._legacy_run_index_fields()` (lines 260-300) hardcodes
run-type-specific field mappings for "parse", "acquisition", "tree", and "retrieval".
This is a backward-compatibility shim **inside a file that was just created in this diff**.
The new storage layer was born with legacy debt.

### 3.3 `TranslationAdapter` Protocol — Zero Implementations

`src/nullvector/ingest/protocols.py` defines `TranslationAdapter` (line 19) — a protocol
for translating external payloads into NullVector's domain types. There are **zero
implementations** anywhere in the codebase. This is a speculative abstraction.

### 3.4 15 One-Line Logging Wrapper Functions

`src/nullvector/observability/logging.py` (287 lines) defines 15 functions like:

```python
def log_page_native_parsed(logger, *, document_id, page_index, block_count):
    log_event(logger, "PageNativeParsed", document_id=document_id,
              page_index=page_index, block_count=block_count)
```

Each function adds zero validation, zero type safety, and zero logic beyond naming
keyword arguments. They replaced 15 typed Pydantic event classes (which was over-engineered
in the other direction), but the replacement is equally boilerplate-heavy. Calling
`log_event(logger, "PageNativeParsed", ...)` directly would be identical.

### 3.5 100+ Symbol Re-Exports in `__init__.py`

`src/nullvector/__init__.py` re-exports **96 symbols** from domain sub-modules, plus
lazy-loads another ~20 service-level symbols. `domain/__init__.py` has its own 80+ line
`__all__` list. This creates massive coupling — changing any internal name requires
updating three `__init__.py` files.

### 3.6 `domain/tree.py` — 915 Lines, ~70 Pydantic Models in One File

This single file contains the entirety of the tree hierarchy domain model. While the
models themselves are well-designed, having 70 models in one file makes navigation,
testing, and change impact analysis unnecessarily difficult.

## SECTION 4: MISSING DEPENDENCIES

### 4.1 `pytest-asyncio` — Referenced But Not Installed

`CLAUDE.md` and `docs/` reference pytest-asyncio. `pyproject.toml` does not include it.
If any tests are async, they will either silently not run or fail.

### 4.2 `pytest-mock` — Referenced But Not Installed

`docs/coding-standards.md` mandates `pytest-mock`'s `mocker` fixture. `pyproject.toml`
does not include it. Tests use manual mock adapter classes instead, which is why there are
elaborate custom fakes like `SequencedAdapter`, `CaptureDecompositionAdapter`, etc.

## SECTION 6: GIT HYGIENE

### 6.1 Uncommitted Diff is 92 Files / ~24,500 Lines

The working tree has a massive uncommitted diff touching every module. This is at least
four separate migrations happening simultaneously:
1. EventBus to stdlib logging
2. Old artifact stores to `DocumentStore` protocol
3. `multimodal_gateway` deletion and fold into `llm/`
4. Domain model split (`models.py` into `common.py`, `events.py`, `gateway.py`, `ledger.py`, `retrieval.py`, `tree.py`)

These should have been four separate, independently reviewable commits.

### 6.2 Meaningless Commit Messages

```
3f0439d 14032026
9acdff7 14032026
3c417ae 13032026
```

Three of the last five commits are just date strings. This violates the project's own
documented Conventional Commits standard and makes `git log` / `git bisect` useless.

### 6.3 No CI Pipeline

Despite `docs/development-workflows.md` describing GitHub Actions, commitlint, pre-commit
hooks, and automated releases — none of these exist. There is no `.github/workflows/`
directory, no `.pre-commit-config.yaml`, no `commitlint.config.js`.

## SECTION 7: DEPENDENCY CONCERNS

### 7.1 Exact Version Pins on PDF Libraries

```toml
"PyMuPDF==1.27.2",
"pypdf==6.8.0",
```

Exact pins (`==`) are unusual for library dependencies and will prevent security patches.
If reproducibility is the goal, the lockfile (`uv.lock`) is the correct mechanism — not
version pins in `pyproject.toml`.

### 7.2 Aggressive Lower Bounds

```toml
"pydantic>=2.11.0,<3.0.0",
```

Pydantic 2.11 was released very recently. This excludes users on Pydantic 2.9 or 2.10,
which may be unnecessary if the features used are available in earlier 2.x versions.

### 7.3 `filterwarnings = ["error::DeprecationWarning"]`

Good practice, but combined with untyped third-party dependencies (`litellm`, `fitz`),
any deprecation warning from upstream will break tests. This should be paired with
per-module warning suppressions for known third-party issues.

## SECTION 8: RECOMMENDATIONS

### Immediate (Block Further Development)

1. **Delete dead artifact stores**: Remove `ingest/artifacts.py` and
   `ingest/acquisition_artifacts.py` if they are fully replaced.
2. **Fix cookbook imports**: Update notebooks referencing deleted `multimodal_gateway`.
3. **Add missing dev dependencies**: `pytest-asyncio`, `pytest-mock` to `[project.optional-dependencies.dev]`.
4. **Complete `tree/service.py` migration**: Pick one persistence pattern and finish it.

### Short-Term (This Sprint)

5. **Rewrite all four docs files** to describe the actual project. Every claim should be
   verifiable by reading the code.
6. **Rename `StrataModel` to `NullVectorModel`** or similar. Complete the project rename.
7. **Consolidate `json_safe`** to one canonical location with zero re-export shims.
8. **Move I/O-performing unit tests** to `tests/integration/`.
9. **Create `tests/conftest.py`** with shared fixtures.
10. **Commit the 92-file diff** as separate, atomic commits — one per migration.

### Medium-Term (Next Sprint)

11. **Simplify `DocumentStore` protocol**: Collapse identical `*_ref` methods. Consider
    whether `ScopedDocumentRun` delegation is worth 120 lines vs. passing scope params directly.
12. **Remove `_legacy_run_index_fields`** from brand-new code. If legacy compatibility is
    needed, handle it at the migration boundary, not inside the new storage layer.
13. **Delete speculative abstractions**: `TranslationAdapter`, empty `api/`, `compat/`,
    `workflows/` modules.
14. **Inline logging wrappers**: Replace 15 one-line functions with direct `log_event()` calls.
15. **Set up CI**: Even a basic GitHub Actions workflow running `make ci` would catch
    half the issues in this report.
